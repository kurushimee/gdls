# 07. Maintenance

gdls is a port. Its correctness is defined by an upstream project that keeps moving, so maintenance is mostly about staying in sync with Godot and keeping the measurements honest.

## 1. Tracking Godot

The source of truth is a local checkout of official Godot (`godotengine/godot`) at tag `4.6.3-stable`, never these documents. When Godot's GDScript module changes, for example when the port rebases onto a newer 4.x, re-apply the corresponding tokenizer, parser, and analyzer diffs from the Godot tree and refresh the vendored corpus in the same change.

This is why the port mirrors Godot's structure function for function. Structural parity is what keeps an upstream diff re-applicable; a "cleaner" Rust rewrite of a function would have to be re-derived from scratch every time that function moves.

**Derive, do not transcribe.** Every enum, count, and message template comes mechanically from the Godot source. Confirmed at `4.6.3-stable`: `TokenKind` has 100 kinds (`gdscript_tokenizer.h`), and the warning set is 45 active plus 3 deprecated (`gdscript_warning.h`, the 3 behind `#ifndef DISABLE_DEPRECATED`) for 48 codes. `TokenKind` is `#[repr(u8)]` indexing a parallel names table, with a `const _: () = assert!(...)` guard in `token.rs` that fails the build if the two drift apart.

**Renames are a last resort.** A symbol is renamed only when a Rust keyword forces it (`SELF` to `SelfKw`, `TK_CONST` to `Const`), and the reason is documented at the site.

## 2. Regenerating the native API

`extension_api.json` is regenerated whenever Godot's native classes change, which in practice means on every engine rebuild. In a session that happens on its own: the watcher reloads the DB when the file changes, and the auto-dump regenerates when the binary or the project's `.gdextension` set changes (`03-indexing-freshness.md` §1).

The embedded stock 4.6.3 surface, the fallback for a machine with no Godot at all, is regenerated by `scripts/regen-stock-api.py`. It must be built with `--dump-extension-api-with-docs`; the `embedded_stock_db_loads` test pins the prose so a regeneration with the wrong flag fails loudly instead of silently emptying every hover.

## 3. The ratchets

Both conformance floors sit at 1.0000 with empty known-failures lists (`06-testing-fidelity.md` §3). CI enforces them on every change, which is what prevents silent fidelity regressions as the port evolves.

Raising a floor is deliberate: update the floor file and say so in the commit message. Lowering one is not a normal operation.

## 4. The release gate

Before tagging a release, run the diagnostics sweep on both acceptance projects, comparatively against the previous release binary (`06-testing-fidelity.md` §6). `--strict` plus the warning histogram, error baselines holding, and the private project swept on Windows with the Windows binary. A navigation walk is not a diagnostics gate.

The five-target fuzz gate (`parse`, `analyze`, `index_invariants`, `complete_context`, `scene_parse`) runs before a release too. Any panic blocks it.

CI runs the same four steps on `ubuntu-latest` and `windows-latest`. The local loop only covers the Linux half, and the Windows leg has stayed red across a dozen merges before because nothing in the merge loop surfaces it. Check `gh run list --branch main` after merging.

## 5. Known risks

| Risk | Likelihood | Mitigation |
|---|---|---|
| Analyzer fidelity gaps, gradual and `Variant` typing especially | High | Corpus plus differential oracle plus per-warning unit tests; ratcheted CI fidelity metric. |
| `.out` corpus mixes runtime and debug output | Medium | The curation layer filters down to the parse and analyze subset. |
| GDScript evolves across 4.x | Low to medium | Track the Godot source; re-port from the gdscript-module diffs. GDScript is stable and churn is low. |
| `extension_api.json` drifts from a rebuilt engine | Medium | The watcher reloads on change; the auto-dump regenerates; degrade gracefully if stale or absent. |
| GDExtension classes absent from the API dump, or shipping no docs | Medium | Multi-source capture (in-project dump plus `doc_classes` XML); enumerate via `.gdextension`; degrade to dynamic with a notice. |
| Performance at 10k files | Medium | Eager-interface and lazy-body split; dependency-tracked invalidation; the memory-pressure ladder; the warm-start cache. |
| LSP position-encoding and large-file edge cases | Low | UTF-16 conversion tests; incremental sync tests; UTF-8 and UTF-32 negotiation. |
| Scope creep into running GDScript | Low | An explicit non-goal; the compiler and VM are excluded by design. |
